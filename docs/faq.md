# 常见问题

## 找不到素材目录

Docker：检查宿主目录是否已实际挂载；网页使用容器内路径。新增挂载后重建容器，再重新打开选择器。设置 `ARCHIVER_ROOTS` 时，范围必须包含需要使用的容器路径。

飞牛 FPK：在应用中心为应用添加目录授权，源目录至少可读、输出目录可读写。新增后刷新授权目录；查询失败会报错，不会退回任意目录访问。

## 输出不可写

Docker：确认输出挂载没有 `ro`，PUID/PGID 与 NAS 用户数字身份匹配，文件夹权限和 ACL 允许读写及穿越。服务不会自动递归修改输出属主。飞牛 FPK：检查应用授权和系统 ACL。

普通 POSIX 模式位不能完整表示飞牛 ACL 的实际权限，不要仅根据 chmod 数字判断访问能力。

## 为什么没有马上生成副本

扫描是预览阶段，确认后需要手动开始归档。复制结果和错误可在“任务记录”中查看。

## 为什么日期是“日期未知”，或年月与预期不同

图片、视频采用内嵌的拍摄/录制时间，不用文件系统修改时间补齐缺失拍摄日期；文档采用修改时间。带时区的时间转换到北京时间 UTC+8，年月跨日、跨月或跨年可能与原始时区不同。没有时区的信息按原值处理。修改容器 TZ 不改变归档规则。

## 同名文件会被覆盖吗

不会。相同目标目录内按完整内容摘要去重，相同内容会跳过；同名但不同内容生成带标识的不同副本。变更规则后可能在新的目录产生副本。

## 为什么修改规则后还要重新扫描

扫描和复制期间会锁定设置；预览完成后修改设置，开始/继续/重试按钮将禁用，直到重新扫描。历史任务显示它实际采用的设置。预览代表扫描时的素材和规则。源素材在扫描后改变会拒绝复制，需要重新扫描；扫描容量也是当时的估计。

## XMP 为什么进入待处理

支持同目录同主文件名（如 `IMG_001.xmp`）和含原扩展名（如 `IMG_001.CR3.xmp`）。多个照片或多个 XMP 候选、未支持的编辑版本命名、已有配套内容变化或多个既有照片名称会显示待处理原因。不会任意选择版本或覆盖旧副本。原件仍保留，补齐或厘清来源后重新扫描。

## 同名的照片与视频为什么没有配成 Live Photo

同名不足以确认配对，需要从照片与视频读取一致且唯一的受支持关联标识。有线索但缺少成员或存在歧义时进入待处理；普通独立照片与视频仍按原分类。目录与名称一致不保证 Apple Photos 可以播放。详见[关联资源说明](associated-resources.md)。

## 照片已归档，后来新增的 XMP 会跳过吗

重新扫描会单独核对需要的成员。唯一的既有相同照片会作为补齐配套的名称依据；不会因照片重复而整组跳过。若已有配套内容不同或存在多个照片名称，进入待处理，等待版本策略确定。

## Docker 重建后要求重新设置账号

检查是否持久挂载 `/config`，以及是否继续使用原宿主目录。账号、会话和任务都在该目录中；空目录会被视为新安装。不要把源素材目录挂到 `/config`。

## Docker Hub 或 GHCR 拉取超时

先确认镜像名正确：`superdaxigua/material-archiver:1.3.1` 或 `ghcr.io/superdaxigua/material-archiver:1.3.1`。两仓库公开，无需登录。网络超时不代表镜像不存在；检查 NAS 网络与镜像仓库连通性。Docker 客户端/终端的网络设置不一定等于 Docker 服务的网络设置。

## 8765 端口被占用

Docker 映射改为 `8766:8765`，浏览器改访问 8766。不要修改冒号右侧的容器端口。尤其注意同一 NAS 的飞牛 FPK 和 Docker 版本默认都使用 8765。

## HTTPS 页面能打开但不能登录或开始归档

反向代理必须保留浏览器请求的原始 Host（包含非默认端口），不能换成容器名或内部地址。修正代理后，从最终 HTTPS 地址重新验证登录和写操作；不要关闭跨站写入防护。

## 需要反馈问题

在 [Issues](https://github.com/superdaxigua/material-archiver/issues) 提供版本、平台、部署方式、复现步骤及脱敏后的报错。不要提交真实账号、密码、令牌、Cookie、完整私密路径或素材原件。
